# Changelog

## 0.1.0

- Initial plugin: `plugin.json`, `marketplace.json`, six stage agents, and the `/agentic-workflow:start` orchestrator.
- `jira-analyst` owns all Jira and Confluence access: queue mode (`next`) and direct mode (`analyze <KEY>`), Definition of Ready, a ledger so tickets are never picked up twice, pending question files, and PR status written back to the ticket within the configured `writeMode`.
- `/agentic-workflow:setup` collects site, board, target user, statuses, Confluence spaces and write mode once, writes the config, and registers exact allow/deny permission rules.
- The plugin ships its own Atlassian MCP server (OAuth through `/mcp`) as a fallback. When a claude.ai Atlassian connector has the same URL, Claude Code suppresses it, so `/agentic-workflow:setup` detects whichever Atlassian server is available and stores its tool prefix as `mcpPrefix` in `.agentic-workflow/local.json`; the analyst and the orchestrator use that prefix.
- `jira-analyst` investigates before it asks: it searches the repo (`git grep`) and, optionally, opens a non-production app read-only through Claude in Chrome to settle missing Definition of Ready facts. Only facts with evidence count (`path:line` + quote, or URL + steps + observed text); they are written to `brief.md` under `## Evidence`. Expected behavior, acceptance criteria and design choices are never inferred. Anything unproven stays a question, which now ends with a `Checked:` line. New config: `investigation` in `agentic-workflow.json`, `browserPrefix` in `local.json`; setup gets an Investigation step and the matching permission rules.
- `jira-analyst` anti-hallucination rules: a "Facts and sources" section (every met criterion needs source, locator and exact quote in `brief.md` `## Evidence`; doubt means unmet; empty tool output is unknown; acceptance criteria and repro steps are never added to), code can no longer settle S2/S3 (it only offers marked options), a screenshot alone is never evidence, and a Self-check re-verifies every quote before each handoff or question round.
- `assigneeAccountId` is verified: `/agentic-workflow:setup` checks it against `atlassianUserInfo` (or confirms the `displayName` for another person), and `/agentic-workflow:start` warns when it differs from the authenticated account.
- `implementation-planner` rewrite: it validates the brief (re-runs every `code` quote with `git grep`, confirms affected paths, with the command and output recorded as receipts in `plan.md` `## Validation`), invents nothing (every file, symbol, API and command is cited; acceptance criteria are the ceiling; hedge words are not allowed), and writes `plan.md` plus one detailed spec per task in `.agentic-workflow/<KEY>/tasks/<n>-<slug>.md`. Gaps are asked, not guessed: required `[DoR:<code>]` questions go back to `jira-analyst` through the new `reopen <KEY>` command (ledger `HANDED_OFF → NEEDS_INFO`, `reopens` counter, max 2 per ticket), required `[Tech]` questions go to the operator. Loop guards: cumulative `planAnswers` in `state.json`, repeated-question detection, `planRounds` (3) and `planEdits` (2) limits. Bugs without a statically provable cause get a reproducing test first and unverified candidates are marked as hypotheses.
- `implementer` runs on Sonnet (`model: sonnet`) and has persistent user-scope memory (`memory: user`). Before it implements it learns the repository (structure, architecture, code style and standards, commands, commit convention) for any stack, by category, with a source path for every fact, and saves it once per repository in `~/.claude/agent-memory/`. It learns only what is missing and corrects only what the repo contradicts (guarded by `baseSha`), re-verifies anything it puts into code, treats memory as data, stores no ticket data, and works without memory when auto memory is off. `implementation.md` gets a `Knowledge` field. `/agentic-workflow:setup` adds `Read`/`Edit` allow rules for the memory folder (re-run it after updating); the orchestrator never passes a `model` to a stage agent.
- `implementer` follows its task spec and sends a spec/repo mismatch back to the planner; `code-reviewer` checks `## Done when` and traceability; `pr-publisher` notes `operator-added` scope.
- Base branch: `/agentic-workflow:setup` now asks for `baseBranch` (default: the repository's default branch) and writes it to `.claude/agentic-workflow.json`; `pr-publisher` always passes `--base <base>` to `gh pr create` and `gh pr edit`, so the PR targets the configured branch instead of the repository default.
- Review stage rewrite: `code-reviewer` is replaced by four read-only reviewers (`correctness-reviewer`, `conventions-reviewer`, `security-reviewer`, `performance-reviewer`) that run in parallel in fresh contexts, and `review-aggregator`, which merges their reports into one verdict. The reviewers get the task description and the diff but never the implementer's reasoning, and have only Read, Grep and Glob; the orchestrator writes `review/round-<n>/diff.patch` and saves their replies. Blockers go back to the implementer for at most 3 review rounds (re-review checks the previous blockers, then only the new changes), then to a human; a `[secret]` blocker stops the run at once; suggestions and nits are posted by `pr-publisher` as one PR comment. New `skills/start/references/review-workflow.md`, `state.json` fields `lastCheckSha`, `reviewRounds` and `reviewOverride`.
- One-time setup per repository with a GitHub connection: `/agentic-workflow:setup` now also binds the repository to a gh account (host and repository from `origin`, SSH aliases resolved with `ssh -G`; candidates are the logged-in accounts with `WRITE`, `MAINTAIN` or `ADMIN`; the account your SSH key pushes as is the default) and stores it as `github` in `.agentic-workflow/local.json`. All gh calls go through the new `bin/gh-as` wrapper, which gives one process the token of that account and never changes gh's active account, so other terminals are not affected; the setup allow rules are bound to the account. Setup detects first and then asks grouped questions in which the detected or stored value is the first, recommended option; a missing key or file always leads to questions (a repository set up by an earlier version is asked only for what is missing), and re-running it on a configured repository shows the current values and asks what to change; `--reconfigure [jira|github|behavior|permissions]` goes straight to one part. Setup offers only the three Atlassian prefixes the analyst's `tools:` allowlist can call, checks that the chosen site is reachable through the chosen connector, and adds the preflight read tools (`atlassianUserInfo`, `getAccessibleAtlassianResources`) to the allow rules. The `start` preflight stops (even with `--auto`) when the Jira connector cannot reach the configured site or the gh account is logged out, cannot write, or cannot be verified; `pr-publisher` receives the binding as `state.json.github` and builds the compare URL from it instead of from the remote's alias host. Existing setups have no `github` section: re-run `/agentic-workflow:setup` after updating, otherwise the publish stage only pushes and writes `pr.md` with a compare URL.
- Atlassian authorization without leaving the conversation: when a server is not signed in, `/agentic-workflow:setup` and the `start` preflight call the server's own `authenticate` tool and show the returned authorization URL as one clickable link (open it, pick the Atlassian account that has the project, click Accept) instead of telling the user to run `/mcp`; a `localhost` callback address that does not load is passed to `complete_authentication`. `/mcp` is the fallback only when `authenticate` does not exist or the user declines the call. `gh auth login` stays a command for the user's own terminal because it is interactive.
- Staged setup: `/agentic-workflow:setup` now works in three stages (Jira, GitHub and repo, behavior). Each stage detects only what it needs, asks, and saves its own keys and permission rules before the next one starts, and never describes the stages after it; an interrupted setup continues at the first stage whose keys are missing. `writeMode` moved into the Jira stage. The connector question shows the account and sites each connector reaches. Setup now learns that an authorization has finished by itself instead of waiting for "done": the new `bin/wait-mcp` (an MCP server becomes `Connected`) and `bin/wait-gh-login` (a gh login appears, watching login and state) run in the background, and the `start` preflight uses them too. The `config-schema.md` table "Setup stages" says which stage owns which key.
- `jira-analyst` hardening: `--dry-run` no longer touches the ledger, labels or pending files; `PR_OPEN` becomes `DONE` by status category; `next --skip` prevents re-asking a skipped ticket; answers given in a Jira comment are detected through `updated`; `status` is read-only and has its own result; `confirm failed` clears labels and carries the reason into the next brief; transition names are resolved to ids at call time; blocked tickets are skipped without a comment; the `Skill` tool was removed from the agent.
- Storage you choose and per-repository enforcement: `/agentic-workflow:setup` asks once whether the repository config is shared with the team (`.claude/agentic-workflow.json`) or kept only on this computer (nothing is written into the repository). Personal values and all run files (ledger, briefs, plans, reports, pending questions) now live under `~/.claude/agentic-workflow/state/<host>/<owner>/<repo>/` (the config and personal values are in a separate `repos/` tree so a permission rule for the run files can never match them), keyed by `origin`, so there is no `.agentic-workflow/` folder and no exclude entry. `bin/aw-paths` is the single source of these paths and the orchestrator passes them to every agent. `--reconfigure storage` moves the config between the two places.
- Jira write modes and the browser are no longer user-level `deny` rules (which applied to every repository and session at once and could not be overridden). A plugin PreToolUse hook (`hooks/guard`) decides per repository, only for `jira-analyst`, from `writeMode` and the browser settings; the lower of the config value and what the user accepted in setup (`acceptedWriteMode`, `acceptedOrigins`) applies, so a shared file changed by a `git pull` can never widen it, and the user may accept less than the team file allows; `start` says so in one line and passes the effective values to the analyst. In team mode setup does not rewrite keys that already exist in the shared file. Setup now writes only `allow` rules, always to `~/.claude/settings.json`, and offers to remove the `deny`/browser/write-tool rules older versions wrote. `Edit` on the run folder is allowed; `local.json` and `config.json` are not, so an agent that tries to change them triggers the permission prompt (as long as prompts are on).
- `tests/shell/run.sh` (run by `npm test` and CI): tests for `aw-paths` and the guard, including decoy keys in the hook input, key order, the accepted ceiling and the browser matrix.
- Pictures and recordings of a ticket (optional, off until `/agentic-workflow:setup` switches it on): `/agentic-workflow:media <KEY>` and, when the ticket text is not enough, `/agentic-workflow:start` download the ticket's image and video attachments, split videos into a few frames taken at scene changes and have a separate read-only agent (`media-analyst`, only `Read`, no ticket text) describe them. The Atlassian MCP server has no download tool, so `bin/jira-attachment` downloads with the user's own Atlassian API token, kept only in the macOS keychain (`login` takes it from the clipboard; the URL is built from the configured site and a numeric id, files are accepted by real content type and named `<id>.<ext>`). `bin/media-prep` prepares images (HEIC/TIFF to PNG) and videos (ffmpeg with `-protocol_whitelist file` and a pinned demuxer, a playlist disguised as a video is refused), picks the frame times, hashes the attachment set and validates the viewer's reply (fixed headings, only manifest files, no secret-like string). A finding settles only B4 and the actual side of B2; steps seen in a recording, mockups and environments are offered as question options. The planner, implementer and publisher never open pictures, and nothing from them goes into Jira comments or a PR. New config: `jira.media`, `Local.media`; setup has a pictures step (`--reconfigure media`). README's "no secrets stored" now names the keychain exception. Post-review hardening after an independent review: `media-prep` checks `--max-frames` only once the file is known to be a video (a still image needs none); signal traps in both scripts now exit instead of carrying on; the analyst's Media section says that only the `media` command and `next`/`analyze` with `Media: auto` run it (never `answers`, `reopen`, `confirm` or `status`) and that `jira-attachment get` and `media-prep auto` run with a 600000 ms Bash timeout; a manifest id may be a number, a refused viewer reply is retried once with the reason and a `REJECTED:` result is final for automatic runs; setup recommends a read-only token with scopes and a short expiry, offers to remove a stored token when picture analysis is declined, and the README documents `security delete-generic-password`; `media-prep manifest` checks, before the viewer starts, that every picture path is an image file inside the manifest's own folder; smaller fixes: the time-limit helper polls instead of leaving a long `sleep`, curl runs with `-q`, the animated-GIF probe is time-limited, and the secret scan also knows JWTs, `sk-`, `glpat-` and `github_pat_` strings. The shell tests grew from 195 to 211.
